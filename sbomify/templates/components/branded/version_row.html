{% comment %} One product's answer inside c-branded.version-check: the product, its status, what to do, and the versions it affects. The versions are chips rather than a bulleted column. They are short and a reader scans them for one value, so a wrapping row holds a dozen in the space a list gave to three. Past `limit` (default 8) the rest fold behind a native
, the same :has() fold as c-lists.folding, so the toggle works before scripts load. It is restated here rather than nested because each chip binds its own match state, which that component has no way to carry. While a version is typed the row says whether it is affected, as a badge whose variant the versionCheck component binds, and each chip says whether its range holds the version through data-match: a match is tinted, a miss recedes, and a folded match unfolds, so the chip that answers is never the hidden one. Every recipe is keyed off that attribute, so the page passes data, never a class. The default slot is what to do, in a sentence. The meta slot is the reason a product is not affected, and the eyebrow slot names the vulnerability when an advisory has several. They are slots rather than props because a page sets them conditionally, and a prop set to an empty string still renders. key ties the row to its entry in the version-check's ranges, label names the version list for a screen reader. {% endcomment %}
