{% comment %} The text input, in plain Tailwind utilities. Email, password, number, url and the rest are this component with a type; there is no separate file per type because nothing about the recipe changes. state is one conditional segment holding the resting border colour and the focus ring together, so a field can never carry two of either. The focus border stays primary in every state, as it always has: the pseudo-class outranks the resting colour. A field whose validity is only known in the browser binds data-state instead: the recipes below are keyed on that attribute, so an Alpine editor writes ``::data-state="formErrors.name ? 'error' : ''"`` and never a class. They are the same two recipes the prop renders, and they outrank the resting one by specificity, so a field can never carry two border colours. Wrap it in c-forms.field for a label and a hint. required, disabled and readonly are declared props so a falsy value renders no attribute at all; everything else (autofocus, x-model, hx-*, aria-*) flows through attrs. {% endcomment %}
