{% comment %} An identifier you click to copy: a monospace chip that confirms in place rather than raising a toast, because these sit in page headers and identifier tables where one toast per click is far too loud. For a labelled control beside a value already on the page use c-copy-button; for a secret use c-token-display. The chip is a button, so the keyboard reaches it and it announces itself as an action. The value and the copy handler are the caller's: it brings the x-data that holds them (copyableValue) and binds the confirmation with ::data-copied="copied", the way a dynamic badge binds its variant. The copied recipe repaints surface, hairline and ink together off that one attribute, so the look cannot drift from the state, and the icon reads the same marker from the group rather than carrying a second copy of it. The icon is here rather than in the slot because it is the chip's own furniture: the slot is the value. The chip states no line-height, which is the one place the usual rule is wrong: its font-size is an arbitrary value, so Tailwind attaches no line-height to cancel, and the public trust-center pages read 1.6 where the app reads 1.5. A stated 1.5 would shorten every identifier chip on those pages by a pixel a line. {% endcomment %}
