Nothing is deleted until a person reads what is about to go and presses the button that names it: the bulk bar's Delete only opens this dialog (confirmDelete()), and the dialog is the only thing that posts. It reads the tableSelection state on the shell, so it goes inside the shell like the bulk bar. The dialog names the count and lists the first five rows by name, then how many more, so a select-all that caught more than intended is visible before it is acted on. The delete button repeats the count ("Delete 3 components"), because a button labelled only "Delete" confirms nothing. action is the URL the selection posts to, each selected id as one name field ("ids" unless name says otherwise), with the CSRF token. Without htmx it is a plain form post and the page that answers decides where to go next. With htmx it posts in place: hx_target and hx_swap say what the response replaces, a success empties the selection and closes the dialog, and a failure keeps both so the person can try again.
