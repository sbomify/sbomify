{% comment %} The table, inside the box a wide table scrolls in: the overflow belongs here, never to the page body. Cells own their padding and their rules, so the table itself only sets the collapse model. fixed gives every column an equal share and centres each one between the first and the last, which is how a table with a trailing actions column keeps its left and right margins symmetric. A cell that states its own alignment (the end prop, the actions column) marks itself data-cell-end and is left alone, so a column that asked to sit right never drifts to the centre. sized fixes the layout without touching alignment, for a table whose header cells state their own widths and whose values read as prose: fixing the layout is what keeps a long package name wrapping inside its column instead of pushing the table wider than the panel. The two share the layout and differ in the alignment they impose, so they render as one conditional segment and a table can never take both recipes. Sortable tables use sized and give their non-name headers widths. The remaining space belongs to the name. Set a minimum table width when those columns need horizontal scrolling on a phone. Rows never participate in column sizing. Long unbroken values wrap inside their cells; use the cell's nowrap prop for values that should ellipsise instead. The viewport opts out of scroll anchoring so reordering rows cannot move the page. Its marker lets the shared sort behaviour retain horizontal position and keyboard focus through a server swap. class is layout for the scroll box; attrs land on the table. {% endcomment %}
