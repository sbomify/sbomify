The row says what it is in one line (the component, where it came from, how many rulings, what approving would hide) and opens to the evidence: the submitter's notes, each ruling, the fix it links to, and anything the queue could not read from the file. Approve and Reject stay on the row so a reviewer never has to open one to decide it. item is a row from services/vex_review.submission_row. decide_url is the review panel's decision endpoint; the row posts its own id to it. open starts the row expanded. can_decide renders the two actions; without it the row is read-only. Approve posts straight away. Reject dispatches vex-reject with the row's id and name, and the panel's one dialog asks for an optional reason, so the note is offered where it matters instead of on every row.
